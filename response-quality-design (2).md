# Response Quality — build spec (v8, implementation-synced)

Four dimensions — **accuracy, completeness, relevance, task_success**. Each section opens with a **design flow** paragraph (what happens, in order, with the research reasoning and the exact computations written into the narrative), followed by a compact reference table. Rule throughout: **AI extracts and judges yes/no; code computes every number.** Synced to the implemented `rq_eval` system.

**Tier legend:** `[T1]` pure code · `[T2]` fixed model, output thresholded to a boolean/label *in code* · `[T3-gen]` pinned generation (builds a frozen reference) · `[T3]` judge (one yes/no) · `[oracle]` human-maintained config file.

---

## 0.1 The provider roster — every tool in the system, defined

All model/tool access goes through **seven typed interfaces**, each with a deterministic **mock** (offline dev) and a **live** implementation (target machine), constructed only by the `ProviderFactory` from `config.yaml`. If a section names a provider, this is what it is:

| Provider | Signature | Mock implementation | Live implementation | Used by |
|---|---|---|---|---|
| **JudgeProvider** | `binary(question, context) → {verdict: bool, reason}` | seeded hash of the question text → stable bool | **Bedrock Claude** via `boto3` Converse | every `[T3]` atom; interface exposes *no* numeric output, structurally enforcing booleans-only |
| **GeneratorProvider** | `generate(prompt, seed) → text` | parse/rule-based stand-ins (e.g. clause-split "extraction") | **Bedrock Claude** via Converse | every `[T3-gen]` step: claim extraction, unit drafting, reverse-questions, objective/outcome decomposition |
| **GroundingProvider** | `entails(premise, hypothesis) → {label ∈ {E,N,C}, raw_score}` | token-coverage + negation heuristic: `cov = overlap(hyp, prem)`; `cov ≥ contra_tau ∧ negation-mismatch → C`; `cov ≥ entail_tau → E`; else `N` | **Bedrock ApplyGuardrail** contextual-grounding (`score ≥ entail_tau → E`, else `N` — **no C label**) or **fairseq RoBERTa-large-MNLI** via torch.hub (native 3-way, `argmax{C,N,E}`) — selected by `models.nli` | the **one NLI, three premises**: groundedness (premise = context span), attribution (premise = *cited* chunk), source-quality supports (premise = source), completeness assignment, task-success coverage |
| **RelevanceProvider** | `score(query, text) → float` (thresholded in code: `≥ relevance_tau → on-topic`) | `jaccard(query, text)` token overlap | **Bedrock ApplyGuardrail** contextual-grounding **relevance** score | relevance Method B; per-claim on-topic |
| **EmbeddingProvider** | `embed(texts) → vectors` | 64-dim md5-hashed token counts, L2-normalized (cosine ≈ shared-token rate) | **Bedrock Titan Text Embeddings V2** via InvokeModel | Method A cosine; completeness dedupe; similarity pre-filters |
| **SourceQualityProvider** | `adequate(source, claim) → bool` | config default (`source_adequate_default`) | Evidence build §3: `mean(7 property booleans) ≥ adequacy_threshold` | accuracy atom 3 |
| **AttributionProvider** | `attributed(claim, cited_chunk) → {bool, confidence}` | mock entails on the cited chunk | Evidence build §4: 3-way verdict + conformal confidence | accuracy atom 4 |

Supporting non-model tools: **`T1Tools`** (`re`-based number/citation parsing, conjunction-split, pattern checks), **`ResolverProvider`** (mock: fabricated-marker check → live: `urllib` HEAD / DOI registry; used by Evidence's fabrication gate + source reachability), **`SandboxProvider`** (config-gated execution interface for task_success's `executable` verifier — currently a heuristic until wired), and the **formula registry + statistics** below. Packages actually imported: **pydantic**, **PyYAML**, stdlib (`hashlib`, `re`, `math`, `json`, `sqlite3`, `urllib`), **boto3**, **spaCy `en_core_web_lg`** + **coreferee** (live NLP), optional **torch+fairseq**. *Not* used despite earlier drafts: `numpy`, `scipy` (all stats are stdlib `math`), and the `ragas` package (Method A implements the RAGAS *method* directly).

**Formula registry** (`scoring/formulas.py`) — every DimensionResult's `formula_id` is one of these pure functions over AtomRecords, which is what makes replay possible: `mean = Σv/n` · `weighted_mean = Σv·w/Σw` · `conjunction_weighted_mean` (group by subject, `correct = AND(verdicts)`, then `Σ correct·w/Σw`) · `relevance_capped_mean` (`abstain_relevant → 1.0`; else `mean(responsive)`, capped at `off_ask_cap` when answer-level on-ask fails) · `task_success_weighted` (`impossible → 1.0`; else `Σ outcome·w/Σw`) · `unsupported_rate = 1 − Σv/n`.
**Statistics** (stdlib `math`): **Wilson 95% CI**, `z = 1.96`: `center = (p̂ + z²/2n)/(1 + z²/n)`, `half = (z/(1+z²/n))·√(p̂(1−p̂)/n + z²/4n²)`, clamped to `[0,1]`, `n = 0 → (0,1)` — the interval you can honestly claim for a proportion at small n. **Bands:** `≥ G → "G"; ≥ A → "A"; else "R"` (default `G = 0.90, A = 0.75`). **Min-n abstention:** `abstain ⟺ n < min_n`.

## 0.2 Shared claim-extraction pipeline (build once)

**Design flow.** Accuracy, completeness, and relevance all operate over the answer's atomic claims, so extraction runs once and is cached. The answer is first **segmented** into sentences — mock: `re` splitter; live: spaCy — because every later stage needs a bounded unit `[T1]`. Each span is then classified **verifiable vs unverifiable** `[T3-gen]`, the correction [VeriScore](https://aclanthology.org/2024.findings-emnlp.552/) (EMNLP 2024) made to FactScore/SAFE, which extract *everything* and thereby punish an answer for its legitimate opinions and hedges; only spans that "can plausibly be proven true or false" continue, the rest route to uncertainty/actionability. Verifiable spans are decomposed into **atomic claims** using **Claimify's** (2025) selection → disambiguation → extraction staging — the disambiguation step *flags* rather than guesses when context can't resolve a reading, avoiding FactScore's run-together subclaims. Each claim is then **decontextualized** `[T2 coreferee + T3-gen]`: "His notable credits include The Game" is unverifiable until "His" resolves, and per [Molecular Facts](https://arxiv.org/abs/2406.20079) (2024) and [DnDScore](https://aclanthology.org/2025.emnlp-main.1205.pdf) (EMNLP 2025) the decontextualizing context travels *with* the claim to the verifier. Finally, because decomposition is provably method-sensitive (Wanner et al., 2024) — different decomposers yield different scores — the extractor prompt+model are **pinned** (`pins.extractor_version`) and **stability is measured**: `stability = |∩ claim-ids| / |∪ claim-ids|` across N re-runs, logged as a property of the reference, not assumed.

*Output:* cached `Claim` objects `{id (content-hash), text, source_sentence, verifiable, decontextualized, citation?, extractor_version}`.

*Three axes, two dimensions:* **on-topic** and **responsiveness** live in **relevance** (accuracy imports responsiveness); **goal accomplishment** lives in **task_success**. They dissociate — relevant-but-unsuccessful; true-but-off-ask — and only collapse on trivial factual asks.

## 0.5 Contracts, records & audit

Every yes/no becomes an **AtomRecord** `{question, tier, verdict, evidence, grader_id, model+version, seed?, timestamp}` in an append-only store (JSONL or `sqlite3`); every dimension emits a **DimensionResult** `{dimension, score, band, CI, n, inputs_hash, atom_ids[], formula_id, abstained}`; and `audit/replay.py::ReplayVerifier` recomputes every score from `atom_ids + formula_id` with **no model call** — T1 atoms bit-for-bit, T2 from the stamped label, T3 from the logged verdict with model+version stamped so drift is detectable. Mismatch = defect. Generated references carry `version + corpus_hash + pinned_model + seed`; certification runs use pinned references. Flipping `mode: mock → live` swaps providers with no change to any formula.

## 1. accuracy — MAJOR · derived — `Σ correct·w / Σ w`

**Design flow.** Accuracy is deliberately *not* an independent scorer: it composes four booleans that other machinery already computes, because "is a sourced claim accurate" factors into checks with better-suited owners, and averaging them would launder weak links. For each cached claim, the pipeline asks: is it **grounded** — do *all* of the claim's triplets carry label `E` from the `GroundingProvider` (the [RAGAS-faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/) form, `|supported|/|total|`, decided by a fixed MiniCheck/HHEM-class verifier, never a generative judge); is its source **adequate** — `SourceQualityProvider.adequate()`, i.e. the Evidence build's seven-property mean cleared its threshold, because a claim grounded in a bad source must not count; is it **attributed** — `AttributionProvider.attributed()`, the *cited* chunk entails *this* claim at conformal confidence, catching right-fact/wrong-citation; and is it **responsive** — the per-claim atom exported by relevance (§3), the guard against the true-but-off-question false positive, which accuracy imports and never recomputes. Claims carrying a **number** get a `[T1]` edge-check instead of trusting NLI: `T1Tools` parses the figures and requires `|n_a − n_b| ≤ numeric_tolerance · max(|n_a|, |n_b|)` against the source — because "$1.2B" vs "$1.3B" must fail and entailment models can miss it. The four booleans are **AND-ed per claim** — weakest-link aggregation, because averaging masks a safety-critical weak atom, the failure the aggregation literature names [trust inflation](https://arxiv.org/html/2607.26191) (2025) — and the dimension score is the **weighted mean of correct claims**: `accuracy = Σ correct·w / Σ w` (`conjunction_weighted_mean`), where `w` optionally comes from completeness's vital labels, since a false *vital* claim should cost more than a false *okay* one ([importance-sensitive factuality](https://arxiv.org/pdf/2510.07083), 2025). Claims with **no source at all** can't be graded by any of this — they go to the **unsourced residual**, one `JudgeProvider.binary()` truth call each `[T3]`; claims *derived across* sources go to the shared inference-validity check (Reasoning category — computed once, read by both). A Wilson 95% CI over (correct, total) bounds the score honestly at small claim counts. Per profile: Nexa's trusted corpus makes source-adequacy ≈ 1 and the residual ≈ 0, so accuracy collapses to ≈ groundedness; RavenPack keeps every term live.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| grounded? | T2 — primary | GroundingProvider | all triplets `E` (imported from Evidence groundedness) |
| numeric edge | T1 — override (replaces NLI on numeric claims) | T1Tools | `|n_a − n_b| ≤ tol · max(|n_a|,|n_b|)` |
| source-adequate? | T1 primary · T2 support · T3 sampled residual (disinterest only) | SourceQualityProvider | `source_quality ≥ adequacy_threshold` |
| attributed? | T2 — primary | AttributionProvider | Attributable ∧ conformal confidence ≥ threshold |
| responsive? | T2 — primary (imported) | relevance export | `on_topic ∧ on_ask` (§3) |
| unsourced residual | T3 — residual (only claims with no source) | JudgeProvider | one truth boolean per unsourced claim |
| score | code | `conjunction_weighted_mean` | `Σ AND(4)·w / Σ w`; Wilson CI; band |

**Confirm:** verifier backend; weighting on/off; residual policy per profile; `numeric_tolerance`.

## 2. completeness — MAJOR · two-tier strict vital recall

**Design flow.** Completeness is the false-negative axis — of what a good answer should contain, how much is present — and its central design decision is **where the reference comes from**. A flat "list all the facts" generation puts all trust in one AI recall step; instead the reference is **two-tier**, which is where the current research has converged: [HD-Eval](https://arxiv.org/pdf/2606.08625) (ACL 2024) aligns evaluators through hierarchical criteria decomposition, [Qworld](https://www.alphaxiv.org/overview/2603.23522) (2026) expands each question into a **tree of binary criteria where every leaf is an unambiguous judgment**, and [question-specific rubrics beat generic ones](https://dl.acm.org/doi/10.1145/3702652.3744220) (Pathak et al., 2025). **Tier 1** is the requirement scaffold — `config/requirement_templates.yaml`, an `[oracle]`: human-maintained facets per question-type, each flagged `vital`, in the spirit of [CheckEval](https://aclanthology.org/2025.emnlp-industry.136.pdf) where humans define the taxonomy and the model only populates it. *This is where the evaluator-trust actually splits*: hierarchy alone just relocates the recall risk upward — **fixing** the top tier is what removes it, because coverage now rests on a reviewable file, not a generation. **Tier 2** drafts atomic units under each requirement `[T3-gen via GeneratorProvider]`, top-down from the requirement *and* bottom-up from source sentences overlapping it (catching drop-from-source omission). Every drafted unit must pass the **admissibility gate** before it's frozen — the answer to "how do we keep units genuinely T2-answerable": **atomic** (`T1Tools` conjunction-split finds exactly one proposition), **self-contained** (no leading pronoun after coreferee resolution), and **entailment-decidable** (a one-time `JudgeProvider` admission that checking it needs only the answer text — world-knowledge units belong to accuracy). This guards the [evaluator over-acceptance](https://www.emergentmind.com/topics/llm-generated-rubrics) failure the rubric literature flags, and makes answerability a construction-time property, not prompt-hope. Near-duplicates across the two drafting passes are merged by `EmbeddingProvider` cosine (`≥ dedupe_tau` → drop). **Assignment** is then one binary per unit — `GroundingProvider.entails(answer, unit) == E`, partial support = unsupported (strict) — the binary-judgment structure of [ARGUE](https://arxiv.org/abs/2501.14342) (2025), which credits paraphrase where string-match can't. The headline score is **strict vital recall** = `|vital units supported| / |vital units|`, the metric [TREC 2025 RAG](https://arxiv.org/pdf/2603.09891) found best-suited for response evaluation, automated in the [AutoNuggetizer](https://dl.acm.org/doi/10.1145/3726302.3730090) lineage whose **τ = 0.87** agreement with humans is the validation bar for the unit generator. Two companion numbers come from `two_level_scoring.py`: **requirement coverage** = `|requirements with ≥1 supported unit| / |requirements|` — a whole facet missing is a sharp materiality signal a flat recall dilutes — and **weighted recall** = `Σ recall(r)·w(r) / Σ w(r)` with `w = 2` for vital requirements, normalizing per requirement so a 10-unit facet can't drown a 2-unit one. The vital recall carries a **Wilson CI** and **abstains below `min_n`** vital units — you cannot certify completeness from three facts.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| Tier-1 requirements | oracle — primary coverage guarantee | `requirement_templates.yaml` | question-type → vital-flagged facets |
| Tier-2 units | T3-gen — reference build (pinned, frozen) | GeneratorProvider | top-down + bottom-up drafting |
| admissibility gate | T1 primary (atomic) · T2 assist (coref) · T3 one-time (decidability admission) | T1Tools · coreferee · JudgeProvider | atomic ∧ self-contained ∧ decidable → freeze |
| dedupe | T2 — support | EmbeddingProvider | drop if `cos ≥ dedupe_tau` |
| assign | T2 — primary scorer | GroundingProvider | supported ⟺ `entails(answer, unit) = E` |
| score | code | `mean` + `two_level_scoring` | strict vital recall; req-coverage; weighted recall; Wilson; min-n abstain |

**Confirm:** fixed vs generated Tier-1 per question-type; strict vs weighted; `min_n`; `dedupe_tau`; τ-validation cadence.

## 3. relevance — MAJOR · on-topic + responsiveness — capped mean

**Design flow.** Relevance measures fit to the **question** — on-topic (aboutness) and responsive (the *specific* ask) — and it **owns** the responsiveness signal accuracy imports, so it's computed once, here. It is **T2-primary**, not T3, because two reproducible instruments exist. **Method A** (diagnostic) implements the [RAGAS answer-relevancy](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/) *method* directly — the `ragas` package is not imported: `GeneratorProvider` writes N reverse-questions from the answer (pinned model, fixed seed), `EmbeddingProvider` embeds them and the original question, and the score is pure cosine, `AR = (1/N) Σ cos(E_question, E_reverseQ_i)` — the number is deterministic; only the reverse-question step is generative, which is why A is a diagnostic, not a gate. **Method B** (the default gate) is `RelevanceProvider.score(query, response)` — mock: `jaccard` token overlap; live: the [Bedrock ApplyGuardrail](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-components.html) contextual-grounding **relevance** score — thresholded in code, no generation step at all: the deterministic-first choice. At the **claim level**, each claim gets `on_topic = RelevanceProvider.score(question, claim) ≥ relevance_tau` `[T2]` and `on_ask` — mock: `overlap(question, claim) ≥ 0.5`; live: a `JudgeProvider` coverage call (the mock threshold is a stand-in; the live judge is the real check) — and the exported **responsive atom is `on_topic ∧ on_ask`**, the boolean accuracy consumes. **Abstention** is handled per [Knowing When You Don't Know](https://aclanthology.org/2024.emnlp-main.1268/) (EMNLP 2024): a proper decline to an unanswerable/out-of-scope question sets `abstain_relevant` and scores **1.0** — declining well *is* the relevant response — while a confident off-topic answer does not. The dimension score is `relevance_capped_mean`: `abstain_relevant → 1.0`; otherwise `mean(responsive)` with an **off-ask cap** — if the answer-level on-ask check fails, the score is `min(score, off_ask_cap)` regardless of on-topic volume, mirroring the RAGAS penalty for unfocused answers (over-answering gets the cap plus a conciseness ding, not a zero; multi-part questions score per part and aggregate).

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| Method A | T3-gen (reverse-Q step) + T2 cosine — diagnostic only, never the gate | GeneratorProvider + EmbeddingProvider | `AR = (1/N) Σ cos(E_q, E_gi)` |
| Method B | T2 — primary / the default gate | RelevanceProvider | raw score ≥ `relevance_tau` |
| per-claim on-topic | T2 — primary | RelevanceProvider | `score(question, claim) ≥ relevance_tau` |
| per-claim on-ask | mock: T2 stand-in → live: T3 primary (the real check) | overlap ≥ 0.5 → JudgeProvider | claim bears on the specific ask |
| responsive export | code | — | `on_topic ∧ on_ask` → accuracy |
| abstention | T3 — edge-case only (unanswerable questions) | JudgeProvider | proper decline → `abstain_relevant` |
| score | code | `relevance_capped_mean` | abstain → 1.0; else capped mean |

**Confirm:** A vs B vs both; `relevance_tau`; `off_ask_cap`; on-ask via overlap-threshold vs judge.

## 4. task_success — MAJOR · verifier-routed — `Σ achieved·w / Σ w`

**Design flow.** task_success asks whether the user's **objective** would actually be achieved — fit to *goal*, not question ("fix this code" answered with a correct explanation is accurate, relevant, and a task failure) — and its design correction is that this is **not irreducibly T3**: the agent-eval literature's standard is a **deterministic oracle with the judge as fallback**. Goal achievement is "typically verified by a deterministic oracle — database state, file-system state, or test-case execution" ([Hitchhiker's Guide to Agentic AI](https://arxiv.org/pdf/2606.24937), 2026); [SafeAgentBench](https://arxiv.org/pdf/2412.13178) (2024) pairs an **execution evaluator** (goal-condition state check after running the plan) with a **semantic evaluator** only where state can't capture the outcome; τ-bench-style systems use **hash-based terminal-state matching** ([Unified Framework](https://arxiv.org/pdf/2605.27898), 2026); success validation "is often rule-based" ([Generalizability survey](https://arxiv.org/pdf/2509.16330), 2025); and multi-step tasks are scored by **subgoal decomposition and summation**, SWE-bench-style ([KDD 2025 tutorial](https://sap-samples.github.io/llm-agents-eval-tutorial/2025_KDD_Evaluation_and_Benchmarking_of_LLM_Agents.pdf)). The flow: `GeneratorProvider` **infers the objective** `[T3-gen]` (intent, not literal words — "why is this slow?" implies *and how to fix it*); the question is **classified by keyword match against `config/task_templates.yaml`** `[oracle]`, which returns **verifier-tagged outcomes with weights** — the templates are human-authored and pinned, because per **Konstantinou et al. (ICST 2025)** LLM-written assertions encode the *current, possibly buggy* behaviour rather than the intended one, so outcome checks are human-validated, never agent-authored; the generator **instantiates the outcomes** for this instance `[T3-gen]`; and the **`VerifierRouter`** dispatches each outcome to its tagged verifier: *artifact-presence* → `re` pattern present `[T1]`; *executable* → currently a heuristic (code signals ∧ run-claim present) behind the config-gated `SandboxProvider` interface — **real execution when a sandbox is wired**, the single biggest determinism win still open; *state* → `expected == answer ∨ expected ∈ answer` string/hash match `[T1]`; *constraint* → includes ∧ ¬excludes ∧ word-count bounds `[T1]`; *coverage* → `GroundingProvider.entails(answer, requirement) == E` `[T2]`, reusing completeness machinery; *grounded/responsive* → reuse §1/§3 atoms; *adequacy* → the **only judge call in the dimension** ("addresses the *root* cause", "at the *right* level"). Code computes `task_success = Σ achieved·w / Σ w` (`task_success_weighted`), with a well-scoped impossible task ("can't be done because X") scoring **1.0**, parallel to relevance's abstention. For code/SQL/numeric/structured tasks the dimension is effectively `[T1]` once the sandbox exists; certification runs use pinned templates/outcome sets (the auditable path), live decomposition on novel questions is discovery and honestly more T3.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| infer objective | T3-gen — reference build (pinned for certification) | GeneratorProvider | intent text |
| classify + template | oracle — primary (human-authored) | `task_templates.yaml` | keyword match → tagged outcomes + weights |
| decompose outcomes | T3-gen — reference build (pinned for certification) | GeneratorProvider | instantiate template |
| route: presence / executable / state / constraint | T1 — primary for these outcome types (exec = heuristic until sandbox wired) | `re` · SandboxProvider(heuristic) · match · code | pattern; signals∧claim; `== ∨ ∈`; includes∧¬excludes∧bounds |
| route: coverage / imports | T2 — primary for these outcome types | GroundingProvider · §1/§3 | `entails = E`; reuse atoms |
| route: adequacy | T3 — residual (the only judge call; often zero outcomes) | JudgeProvider | "root cause" / "right level" booleans |
| score | code | `task_success_weighted` | `Σ achieved·w / Σ w`; impossible → 1.0 |

**Confirm:** template taxonomy + verifier tags; **sandbox in scope?**; adequacy weighting.

## Category notes

Build §0.2 first (three dimensions consume it), then §2's units (supplying §1's weights). Responsiveness computed once (§3), imported by §1, ignored by §4. All four **MAJOR**; the only gate touching the category is fabricated-citation (Evidence build). Honest T3 surface: the `[T3-gen]` reference builders (pinned, frozen, stability-measured), the live on-ask judge call, abstention/adequacy/residual booleans — everything else is `[T1]`/`[T2]` + the formula registry, and the **ReplayVerifier proves it**: every score recomputes from logged atoms with no model call.

| Dimension | formula_id | T1 | T2 | T3 |
|---|---|---|---|---|
| accuracy | `conjunction_weighted_mean` | numeric edge; composition; Wilson | grounded/attributed/responsive imports | gen: claims · judge: unsourced residual |
| completeness | `mean` + two-level | scaffold; atomicity; recall math | assignment; dedupe | gen: units · judge: one-time admission |
| relevance | `relevance_capped_mean` | cosine; cap; composition | Guardrail relevance / overlap | gen: reverse-Qs · judge: on-ask (live), abstention |
| task_success | `task_success_weighted` | presence/exec-heuristic/state/constraint | coverage; imports | gen: objective+outcomes · judge: adequacy only |
