# Response Quality — build spec (v8, implementation-synced)

Four dimensions — **accuracy, completeness, relevance, task_success**. Each section opens with a **design flow** paragraph (what happens, in order, with the research reasoning and the exact computations written into the narrative), followed by a compact reference table. Rule throughout: **AI extracts and judges yes/no; code computes every number.** Synced to the implemented `rq_eval` system.

**Tier legend:** `[T1]` pure code · `[T2]` fixed model (NLI / grounding / embeddings), output thresholded to a boolean/label *in code* · `[T3-gen]` pinned generation (builds a frozen reference) · `[T3]` judge (one yes/no) · `[oracle]` human-maintained config file.

**Why `[T2]` is defensible (it leans heavily on NLI):** natural-language inference is a near-solved task — fixed MNLI-class models sit at ~90% human agreement, "consistent with ceiling performance on SNLI" ([Beyond Questions](https://arxiv.org/pdf/2605.26937), 2026) — and on the evaluation tasks this system uses NLI for, a fixed verifier *matches a generative judge*: [DIVER-QA](https://arxiv.org/abs/2511.07659) (2025) shows NLI + a lexical flag reaches GPT-4o's 89.9% on long-form QA at orders-of-magnitude lower cost, and QA↔NLI conversion is a decades-old standard ([survey](https://arxiv.org/pdf/2402.03686)). A fixed model is also *preferable* to a judge here, not merely cheaper: judges carry verbosity/authority/position biases and run [too generous without a reference](https://arxiv.org/html/2607.12885) (2026). Where a residual `[T3]` remains, it is a **single boolean, reference-grounded, and conformal-wrappable** — never a free scalar.

**Two judge roles (see §0.5):** a **ScoringJudge** (the few irreducible score-affecting booleans) and an **ExplanationJudge** (the user-facing summary, read-only, never an input to any score). "Explain, never override" is structural, not a convention.

## 0.1 The provider roster — every tool in the system, defined

All model/tool access goes through **seven typed interfaces**, each with a deterministic **mock** (offline dev) and a **live** implementation (target machine), constructed only by the `ProviderFactory` from `config.yaml`. If a section names a provider, this is what it is:

| Provider | Signature | Mock implementation | Live implementation | Used by |
|---|---|---|---|---|
| **ScoringJudge** | `binary(question, context, reference?) → {verdict: bool, reason}` | seeded hash → stable bool | **Bedrock Claude** via `boto3` Converse | the irreducible score-affecting `[T3]` atoms only (accuracy unsourced residual, task_success adequacy, rare admissibility/disinterest residuals); returns *no* numeric output (booleans-only, structural); reference-grounded where one exists |
| **ExplanationJudge** | `summarize(DimensionResults, AtomRecords) → text` | templated text stub | **Bedrock Claude** via Converse | the end-of-run user-facing summary **only**; read-only over finished scores; **no verdict field, never read by any `formula_id`** (see §0.5) |
| **GeneratorProvider** | `generate(prompt, seed) → text` | parse/rule-based stand-ins | **Bedrock Claude** via Converse | `[T3-gen]` reference-building only: Tier-2 unit drafting, objective/outcome decomposition, reverse-questions, and the *optional pinned* claim surface-realizer (claim *decomposition* itself is now deterministic parsing — §0.2) |
| **GroundingProvider** | `entails(premise, hypothesis) → {label ∈ {E,N,C}, raw_score}` | token-coverage + negation heuristic: `cov = overlap(hyp, prem)`; `cov ≥ contra_tau ∧ negation-mismatch → C`; `cov ≥ entail_tau → E`; else `N` | **Bedrock ApplyGuardrail** contextual-grounding (`score ≥ entail_tau → E`, else `N` — **no C label**) or **fairseq RoBERTa-large-MNLI** via torch.hub (native 3-way, `argmax{C,N,E}`) — selected by `models.nli` | the **fixed verifier** across the system: §Evidence 1 runs it **per retrieved chunk** to build the **support set `S`** (groundedness); source-quality and attribution **reuse `S`** (set operations, no re-run); completeness assignment, task-success coverage, relevance edges/on-ask, and §0.3 claim-graph edge-confirmation all call it. **One verifier, reused — not one-premise-per-check** |
| **RelevanceProvider** | `score(query, text) → float` (thresholded in code: `≥ relevance_tau → on-topic`) | `jaccard(query, text)` token overlap | **Bedrock ApplyGuardrail** contextual-grounding **relevance** score | relevance Method B; per-claim on-topic |
| **EmbeddingProvider** | `embed(texts) → vectors` | 64-dim md5-hashed token counts, L2-normalized (cosine ≈ shared-token rate) | **Bedrock Titan Text Embeddings V2** via InvokeModel | Method A cosine; completeness dedupe; similarity pre-filters |
| **SourceQualityProvider** | `adequate(source, claim) → bool` | config default (`source_adequate_default`) | Evidence build §3: `mean(7 property booleans) ≥ adequacy_threshold` | accuracy atom 3 |
| **AttributionProvider** | `attributed(claim, cited_chunk) → {bool, confidence}` | mock entails on the cited chunk | Evidence build §4: 3-way verdict + conformal confidence | accuracy atom 4 |

Supporting non-model tools: **`T1Tools`** (`re`-based number/citation parsing, conjunction-split, pattern checks, deixis/comparative tagging for indexical claims, number-provenance tracking for arithmetic edges), a **`ClaimExtractor`** (dependency-parse decomposition — ClausIE/PredPatt-style over spaCy, with an optional pinned surface-realizer; §0.2), the **`ClaimGraph`** service (nodes + typed dependency edges, backward premise-BFS with `networkx` acyclicity/cycle-cut, roots-first resolution, two-verdict propagation, and the force-directed diagnostic render; §0.3), **`ResolverProvider`** (mock: fabricated-marker check → live: `urllib` HEAD / DOI registry; used by Evidence's fabrication gate + source reachability), **`SandboxProvider`** (config-gated execution interface for task_success's `executable` verifier — currently a heuristic until wired), and the **formula registry + statistics** below. Packages actually imported: **pydantic**, **PyYAML**, stdlib (`hashlib`, `re`, `math`, `json`, `sqlite3`, `urllib`), **boto3**, **spaCy `en_core_web_lg`** + **coreferee** (live NLP + dependency parse for extraction), **networkx** (claim-graph resolution + cycle detection + render), optional **torch+fairseq**. *Not* used despite earlier drafts: `numpy`, `scipy` (all stats are stdlib `math`), and the `ragas` package (Method A implements the RAGAS *method* directly).

**Formula registry** (`scoring/formulas.py`) — every DimensionResult's `formula_id` is one of these pure functions over AtomRecords, which is what makes replay possible: `mean = Σv/n` · `weighted_mean = Σv·w/Σw` · `dag_resolution` (accuracy: per-node `successful/total`, where success = passing axiom `AND(grounded, source-adequate, attributed)` OR dependent whose sub-DAG resolves to passing axioms via valid steps; §0.3) · `relevance_capped_mean` (`abstain_relevant → 1.0`; else `mean(responsive)`, capped at `off_ask_cap` when answer-level on-ask fails) · `task_success_weighted` (`impossible → 1.0`; else `Σ outcome·w/Σw`) · `unsupported_rate = 1 − Σv/n`.
**Statistics** (stdlib `math`): **Wilson 95% CI**, `z = 1.96`: `center = (p̂ + z²/2n)/(1 + z²/n)`, `half = (z/(1+z²/n))·√(p̂(1−p̂)/n + z²/4n²)`, clamped to `[0,1]`, `n = 0 → (0,1)` — the interval you can honestly claim for a proportion at small n. **Bands:** `≥ G → "G"; ≥ A → "A"; else "R"` (default `G = 0.90, A = 0.75`). **Min-n abstention:** `abstain ⟺ n < min_n`.

## 0.2 Shared claim-extraction pipeline (build once)

**Design flow.** Accuracy, completeness, and relevance all operate over the answer's atomic claims, so extraction runs once and is cached — and it is **deterministic-first**, not open generation, which is the defensible construction. The answer is **segmented** into sentences `[T1]` (mock: `re`; live: spaCy). Each sentence is decomposed into **content units** by *syntactic/semantic parsing, not a model*: [ClausIE](https://resources.mpi-inf.mpg.de/d5/clausie/clausie-www13.pdf) derives clauses from a dependency parse and maps them to proposition types by clause structure, and [PredPatt](https://arxiv.org/pdf/2403.11903) extracts predicate-argument substructures from a Universal-Dependencies parse — the [Closer Look at Claim Decomposition](https://arxiv.org/pdf/2403.11903) work uses exactly this as a non-LLM decomposer, on the established correspondence between dependency arcs and semantic units (the OpenIE tradition: ClausIE, MinIE, ReVerb) `[T1]`. The **verifiable-vs-opinion** filter is mostly lexical/syntactic (hedge/opinion markers via `re` + POS), residual to a fixed classifier — the [VeriScore](https://aclanthology.org/2024.findings-emnlp.552/) principle (keep only "plausibly provable" spans) without a generative pass `[T1/T2]`. **Decontextualization** is coreference substitution, `coreferee` resolving pronouns/referents `[T1/T2]` (per Molecular Facts / DnDScore, carrying context to the verifier). The **one honest model touch**: parser-derived subclaims "contain only words from the original sentence and are often not grammatical sentences," so a fluent standalone claim can need a small **surface-realizer** — but this is a *pinned, fixed* step ([Abstractive Proposition Segmentation](https://arxiv.org/pdf/2406.19803), a distilled domain-general model), **not** a free "find the claims" call, and it is **droppable**: if the downstream NLI verifier consumes parse-form units without changing its verdicts (a testable property — compare verifier agreement on parse-form vs realized claims), the realizer is skipped and extraction is fully `[T1/T2]`. Because decomposition is method-sensitive (Wanner et al., 2024), whatever the config, the pipeline is **pinned** (`pins.extractor_version`) and **stability is measured**: `stability = |∩ claim-ids| / |∪ claim-ids|` across N re-runs. The residue that genuinely stays model-dependent is *abstractive* content — facts implied but not stated (Claimify's bracketed `[a celebrity]`) — which is **flagged**, not silently generated.

*Tiering note:* this moves claim extraction from the old open `[T3-gen]` to **deterministic parsing + an optional pinned realizer** — decomposition `[T1]`, filter/decontext `[T1/T2]`, realizer `[T2, pinned, droppable]`, with abstractive-implied claims the flagged residue.

*Output:* cached `Claim` objects `{id (content-hash), text, source_sentence, verifiable, decontextualized, citation?, extractor_version}`.

*Three axes, three dimensions — kept orthogonal:* **truth** (grounded/sourced) lives in **accuracy**; **on-topic** and **responsiveness** live in **relevance**; **goal accomplishment** lives in **task_success**. Accuracy does **not** import responsiveness — an axiom is *true*, not necessarily *on-question*; a true-but-off-topic claim is accurate (counts) and separately scores low on relevance, and the aggregator reads them together. They dissociate cleanly (true-but-off-ask; relevant-but-unsuccessful) and only collapse on trivial factual asks.

## 0.3 Claim graph — node value, frame-completeness & DAG accuracy (build once, shared infrastructure)

**Design flow — why the graph exists.** Not every claim is independently checkable, and treating them as if they were is the flaw this section fixes. Some claims are **derived** — "margins improved" when no source states it but it follows from a grounded revenue and cost figure; some are **indexical** — "it is dark" is not even a complete proposition until siblings supply *where* and *when*. Scoring these in isolation is meaningless (an NLI check on "it is dark" returns Neutral because the claim is *incomplete*, not false). So over the cached claims the system builds a **claim graph** — nodes are claims, directed edges are typed dependencies — and resolves it. This is the **entailment-graph** formalism ([Dalvi et al. 2021](https://arxiv.org/pdf/2402.19467) introduced compositional trees where a hypothesis follows from multi-premise steps over verified support facts; [Deliberate Reasoning](https://arxiv.org/pdf/2410.03136), 2024, formalizes reasoning as an entailment DAG `G=(V,E)` with **hyperedges** from a *premise set* to a conclusion — exactly the convergence case), and the recent [From Chains to DAGs](https://arxiv.org/pdf/2601.17593) (2026) shows real reasoning is a DAG with **multi-premise dependencies enforcing acyclicity**, not a chain. The graph is **shared infrastructure**, not a scorer: atomic checks (groundedness, per §1) *ignore* it and stay per-claim; only structural metrics read *projections* of it.

**Three claim types (typed at split time, mostly `[T1]`).** Detection reuses tools already in §0.2. **(1) Independent** — a complete proposition, groundable on its own (the default). **(2) Inference-dependent** — a complete proposition no single source attests, entailed by sibling claims; *detected as a byproduct of the grounding pass* — a well-formed claim with an empty support set `S` (§Evidence 1) but entailed by other claims is inferred, no separate detector needed. **(3) Indexical-dependent** — an *incomplete* proposition with free spatiotemporal/deictic slots; *detected by `T1Tools`* flagging deixis/comparative/evaluative markers ("this", "here", bare "it is dark", standardless "strong/better") via spaCy POS + dependency tags at split time. Type-3 claims are **bound** before scoring: `T1Tools` NER finds the sibling supplying each free slot (a TIME/LOC/quantity entity), the slot is filled, and the completed claim is verified to still entail the original + contain the filler — if binding is uncertain, the claim is flagged `context-incomplete` and routed out of grounding (reported, not guessed).

**Edge finding — the hard part, done the way the research does it `[T1 propose + T2 confirm]`.** The difficulty is entirely "which claims did this one build on," and naïvely testing all premise subsets is combinatorial. The literature's solution — adopted here — is **recursive backward premise identification from each conclusion**, not forward enumeration: the [LLM argument-mining system](https://arxiv.org/pdf/2605.13793) (2026) identifies, *for one target conclusion at a time*, which prior components support it, expands each found premise as a new target in a **BFS**, and restricts candidates to **unvisited earlier nodes only — which enforces acyclicity by construction**. This collapses the combinatorial problem into a series of local "what supports *this* node" questions. For each, the pipeline runs three signals: **(a) discourse markers** `[T1]` ("so", "therefore", "because", "which means") propose a candidate edge cheaply; **(b) topical restriction** `[T1/T2]` — candidate parents are limited to claims sharing entities/numbers (coref + `EmbeddingProvider` clustering) and appearing earlier, keeping the candidate set small; **(c) entailment confirmation** `[T2]` — `GroundingProvider.entails(⋀candidate_parents, claim) == E` confirms the edge, following the **minimal-complete-premise-set** criterion ([ReasoningFlow](https://arxiv.org/pdf/2606.05402), 2026: the parent set must be *complete* — sufficient to entail the step — and *minimal* — removing any parent breaks it), found by greedy reduction rather than subset enumeration. **Convergence (many→one)** is the hyperedge `⋀parents ⊨ claim`; **divergence (one→many)** is a parent with out-degree > 1 — both fall out of the same backward pass. **Numeric convergence gets a near-deterministic aid** `[T1]`: because financial derivations are arithmetic, `T1Tools` tracks number provenance — if a claim's figure is a function of parent figures (profit = revenue − costs), that arithmetic signature *identifies the parents precisely*, the entailment-graph convention of taking premises to be "where the numbers used in the step were first derived" ([ReasoningFlow](https://arxiv.org/pdf/2606.05402)). **Cycles** (a claim set that only supports itself, never reaching an axiom) are cut with `networkx` cycle detection → those nodes fail as unverifiable (no infinite regress). *Honest floor:* edge **recall is the weakest link** — unmarked, world-knowledge-heavy, or convergent-multi-premise edges get missed, and a missed edge makes a valid derived claim look like a failed orphan. So edge-detection recall is **measured against a human-linked sample and reported** as the system's honest error bar on reasoning-structure detection (the [argument-mining survey](https://arxiv.org/html/2506.16383v4), 2025, confirms relation classification is the harder subtask). This is the one place the design is bounded-but-imperfect, and it says so.

**Committed edges (the founding simplification).** A relationship is *topology, not degree*: a "90%-related" edge is incoherent — it blends the graph where the claim is dependent with the one where it's independent, and no single number represents that. So **edges are committed** — thresholded real/not-real at a calibrated cutoff, never carried as a fuzzy fraction. This is what lets the node math (below) stay clean: you condition on a *committed* structure, not a probability-weighted smear of structures. The same discipline governs completeness (a measured ratio) and relationship validity (a **gate**, not a truth-eroding multiplier).

**Resolution & the two verdicts (`[code]` over the graph).** With axioms at the bottom, the graph is evaluated **roots-first to a fixpoint** (topological order): an **axiom** passes iff **grounded ∧ attributed ∧ source-adequate** (the Evidence funnel, §Evidence 1/3/4 — truth only; responsiveness lives in relevance, not the axiom); a **dependent** resolves once its parents resolve. Each dependent node carries **two verdicts**: **local validity** — does this step follow from its parents (`⋀parents ⊨ claim`), a *verification-independent* check in isolation — and **propagated truth** — true iff the step is valid *and* the required parents are true. A **valid step on a false premise is valid-but-false** (`valid ✓ / true ✗`), localized to the false parent, not the reasoning.

**Node value — the core formula.** For each derived node, given parents resolved to committed states: **`node_value = completeness_ratio × min(truth-likelihood of load-bearing parents)`**. *Load-bearing* parents are those whose state, flipped, would change whether the node's logical condition holds (counterfactual) — so satisfied-OR siblings are **excluded** from the min and a false-but-irrelevant sibling can't poison an OR node (AND → min over all; OR → min over the satisfying subset). Relationships **gate**, they don't multiply: a *valid* step doesn't degrade truth, so treating relationship-confidence as a multiplicative fraction would conflate *uncertainty about validity* (which belongs in the calibrated edge threshold) with *degradation of truth* (zero for a valid step), producing pathological rot — instead relationships are committed gates and **only parent truths propagate**, as the assumption-free weakest-link `min` (a product would smuggle in an independence assumption the diamonds violate). A false load-bearing parent contributes ~0 → the node collapses via the min automatically; an incomplete node collapses via the ratio — both failure modes absorbed by one number. A 90%-complete node from true premises yields ≈0.9 — *penalized, not killed, and it propagates forward* (more faithful than a gate declaring the chain dead). **Both factors are logged** (ratio, min, limiting parent) so a failing node's *reason* is recoverable. The node value is **thresholded once, conformally** (§5) — a defensible measured surrogate for P(claim | support), calibrated at the decision, not a raw posterior.

**completeness_ratio — frame-semantic role coverage.** A claim can be logically completed a million ways, so we don't enumerate the ideal premise set — we measure coverage against a **fixed, curated schema from the claim's own predicate**: `completeness_ratio = filled core roles / total core roles` (binary per component). The predicate **evokes a FrameNet frame** whose 2–4 **core roles** are the minimal denominator (looked up, not invented — and derived from the *claim*, not the parents, so gaps stay detectable); SRL fills them (F1 85–91). A role is filled two ways: **direct** — a parent's matching role supplies it (contextual roles: entity, time — aligned role-to-role by filler type + entailment-confirm, so topical nearness alone can't fill a slot); or **derived** — the filler is computed across parents (the *asserted* role, e.g. "profitable" from revenue−costs, which no parent literally contains) via arithmetic number-provenance `[T1]` or `⋀parents ⊨ role-content` `[T2]`. Frames handle context-completeness; arithmetic/entailment handles assertion-completeness. An unfilled role is a *named, typed* gap, classified by FrameNet null-instantiation as **DNI** (recoverable → completer-search over the answer's own claims, feasible because node-completeness is *confined* to a small set) or **INI** (genuine gap → assumption, routed to reasoning's assumption_quality). Each fill is tagged by source (direct/arithmetic ≈ 0 error; entailment carries the NLI ceiling) so the ratio's reliability is visible. Full derivation in the companion claim-graph design sheet and `node-completeness-frame-semantics.md`.

**Accuracy as DAG resolution (per node, not per path).** Accuracy is **`successful claims / total claims`**, equal weight (weighting removed; vital-weighting a noted future item). A claim is *successful* if it is a passing axiom **or** a dependent whose `node_value` clears the threshold. **Per-node counting** makes branching/convergence automatic: an axiom feeding ten branches is counted **once**; a two-parent claim is **one node**; diamonds need no special case. A claim neither axiom nor validly-linked is a **failed length-1 node** (bare assertion — penalized). A non-axiom that *is* a valid link **counts positively though never grounded/attributed itself** — forming a valid claim from evidence is accurate. *Independence, defended honestly:* we count **verification-independence** (each local check is self-contained — "does B follow from A" doesn't depend on "does C follow from A"); we do **not** claim statistical independence — shared-axiom branches are correlated, honored by truth-propagation (a shared false axiom fails everything downstream, proportional to how much rested on it). The **axiom-to-derived ratio is reported** so evidential breadth is visible (ten conclusions on one axiom ≠ ten independent axioms). Numeric edges route to `[T1]` exact-match; the ScoringJudge residual fires only on genuinely bare claims.

**Error tracking — two types.** **Type 1 (decision uncertainty)** — each atom inherits the *measured error rate of its decision-type* (a class frequency, not an instance probability), from calibration against human-labeled datasets (`calibration-datasets-inventory.md`: LLM-AggreFact/RAGTruth for grounding, EntailmentBank/STREET for edges, RDTE for sufficiency, LogiQA 2.0 for AND/OR, FrameNet for frames, FinReflectKG-HalluBench for financial). AtomRecord gains `{source, error_band, conformal_covered}` and propagates **weakest-link** alongside the value, with the limiting atom. **Type 2 (structural uncertainty)** — missed edge, wrong frame, missed implicit role — can't carry an honest ±, so it's **flagged** and counted at answer level as coverage/recall, **never fused into the value**. Answer-level output = value + decision-error profile (by source) + structural-coverage profile (flag counts) + limiting factors. Where a decision-type has no calibration set yet → emit "uncalibrated" flag, never a manufactured number. A single **reasoning-structure calibration harness** measures edge-recall + frame-disambiguation + completeness + AND/OR together (same NLI-ceiling uncertainty) and **gates the two-layer flags** — the graph layer stays off until it clears a bar.

**Projections — one graph, built once, read by many (the isolation rule).** There is **exactly one claim graph**, built once by the shared `ClaimGraph` service; every dimension reads a **different projection**, none rebuilds edges. **Accuracy** reads them as **derivation** (does this chain reach a true **axiom**?); **relevance** reads the *same* support edges as **reachability** (reach a question **anchor**?); **attribution** reads the **axiom subset** (only source-referencing claims carry citations, §Evidence 4); **groundedness** ignores the graph (per-claim, the axiom-*builder*); **reasoning** reads inference-edge *soundness*. A **bare claim** (accuracy: reaches no axiom) and an **orphan** (relevance: reaches no anchor) are *the same unconnected node* against a different root set. Building two graphs would duplicate edge-detection and risk disagreement; scoring independence is preserved by **disjoint projections** — each `formula_id` reads only its own atom type — enforced by the no-shared-scoring-atom test (§0.5). *One shared structure; atomic checks ignore it; each structural metric reads its own projection.*

**Two-layer discipline.** The graph is the **additive, flagged, recall-gated** layer: accuracy's robust core is the per-claim axiom floor (Layer 1, no graph), and DAG-rescue is Layer 2 behind a flag gated on the calibration harness; relevance likewise has a direct core + a scaffolded shared-graph tree (§3). If edge-recall underperforms, the system degrades gracefully to the cores. Edge recall is the honest weakest link — unmarked/world-knowledge/convergent edges get missed, and a missed edge makes a valid derived claim look like a failed orphan — which is exactly why the layer is gated rather than load-bearing ([argument-mining survey](https://arxiv.org/html/2506.16383v4), 2025: relation classification is the harder subtask).

**Visualization (`[code]`, first-class diagnostic).** The resolved graph is logged (nodes + typed edges + two verdicts + both value-factors + flags), so a `networkx` force-directed render is a *view*, not new computation: axioms green roots, derived green/red by chain survival with the *broken step and limiting factor highlighted*, contradiction edges red, orphans floating, a mid-way branch death severing one branch while its sibling survives, completeness gaps named by role. The certification payoff — a reader sees *where* reasoning failed and *what rested on what*, which a scalar can't convey.

*Output:* a resolved `ClaimGraph {nodes: Claim[+type, two-verdicts, value, completeness_ratio, min_factor, limiting_atom, flags], edges: [type ∈ {supports, derives, binds, contradicts}, parent_set, logical_condition ∈ {AND,OR,k-of-n}, confirmed_by], axioms[], failed[], axiom_derived_ratio, decision_error_profile}` — logged, replayable (set-ops + topological eval over stamped labels, no model call), the substrate accuracy/relevance/reasoning project from. **Full model: the claim-graph design sheet.**

## 0.5 Contracts, records & audit

Every yes/no becomes an **AtomRecord** `{question, tier, verdict, evidence, grader_id, model+version, seed?, timestamp}` in an append-only store (JSONL or `sqlite3`); every dimension emits a **DimensionResult** `{dimension, score, band, CI, n, inputs_hash, atom_ids[], formula_id, abstained}`; and `audit/replay.py::ReplayVerifier` recomputes every score from `atom_ids + formula_id` with **no model call** — T1 atoms bit-for-bit, T2 from the stamped label, T3 from the logged verdict with model+version stamped so drift is detectable. Mismatch = defect. Generated references carry `version + corpus_hash + pinned_model + seed`; certification runs use pinned references. Flipping `mode: mock → live` swaps providers with no change to any formula.

**The judge is quarantined off the scoring path — structurally.** Two providers, two roles, enforced by their interfaces. The **ScoringJudge** produces only single booleans, only for the irreducible atoms (accuracy's unsourced-claim residual — open-world fact-checking has no fixed oracle; task_success adequacy — qualitative "root cause / right level"; and the rare admissibility-decidability and source-quality-disinterest residuals), each an ordinary AtomRecord that a `formula_id` may read like any other boolean, and each **reference-grounded** where a reference exists (the residual truth-judge gets the retrieved corpus; adequacy gets the pinned outcome template) because judges are [too generous without a reference](https://arxiv.org/html/2607.12885). The **ExplanationJudge** runs *after* all scores are final, is **read-only over the DimensionResults and AtomRecords**, and writes the user-facing narrative summary — its output has **no verdict field and is never an input to any formula** (the interface returns text, not numbers, and no `formula_id` references it), so it can explain *why* a score is what it is but can never move it. This makes "explain, never override" a property of the code, not a guideline. Net score-affecting judge footprint: a handful of conformal-wrappable booleans, none on the gate path; every other step is `[T1]`/`[T2]`/pinned-generation. This is the reform's target state — see the category notes for the honest list of what stays generative.

**Forward-declared cross-category interfaces (not built here — stubs with defaults, like accuracy's imports).** Relevance's orphan-resolution pass (§3) produces two outputs owned by a dimension in the *Reasoning* category, designed separately. Until it exists they are typed stubs so relevance is independently buildable: `ConsistencyProvider.edge_sound(premise, conclusion) → bool` — is a *stated* inference **valid** (relevance confirms an edge *exists*; this judges whether it *holds*); default stub `true` + flag-for-review, so relevance never silently penalizes reasoning it isn't built to judge. `ConsistencyProvider.route_contradiction(claim, anchor)` — accepts a stranded orphan that **contradicts** an anchor (flood-zone-under-"attractive") for scoring by logical_consistency + completeness; default stub records the routed atom, no-op downstream. Replaced with no change to relevance's code when Reasoning is built — the `SourceQualityProvider`/`AttributionProvider` pattern.

## 1. accuracy — MAJOR · DAG resolution — `successful claims / total`

**Design flow.** Accuracy is **not an independent scorer** — it is the resolution of the claim graph (§0.3): **`accuracy = successful claims / total claims`**, equal weight, counted **per node**. A claim succeeds one of two ways. As an **axiom** (directly verifiable-*true*): the three truth-booleans other machinery already computes must all hold — **grounded** (all its triplets carry label `E` from the `GroundingProvider`, the [RAGAS-faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/) form, a fixed MiniCheck/HHEM-class verifier, never a judge), **source-adequate** (`SourceQualityProvider.adequate()` — a claim grounded in a bad source must not count), and **attributed** (`AttributionProvider.attributed()` — the *cited-or-implicitly-scoped* source actually supports it, §Evidence 4). **Responsiveness is deliberately *not* part of the axiom** — an axiom is about *truth*, not *relevance*; a true, well-sourced, correctly-cited claim is a valid anchor even if it doesn't bear on the question, and can validly anchor derivations. The true-but-off-question case is caught by **relevance** scoring it off-topic (§3) and the aggregator weighing accuracy against relevance — keeping the two axes orthogonal instead of re-coupling them inside accuracy. The three are **AND-ed** (weakest-link, not averaged — averaging masks a safety-critical weak atom, the [trust-inflation](https://arxiv.org/html/2607.26191) failure). As a **dependent** (inference- or indexical-linked): the claim succeeds if its sub-DAG **resolves to passing axioms through locally-valid steps** (§0.3) — so a claim never grounded or attributed on its own *still counts positively* when it is a valid derivation from evidence, because forming a sound claim from established facts is itself accurate. Claims carrying a **number** get a `[T1]` edge-check instead of trusting NLI: `T1Tools` requires `|n_a − n_b| ≤ numeric_tolerance · max(|n_a|,|n_b|)` against the source, since entailment misses magnitude ("$1.2B" vs "$1.3B"). A **bare** claim — no source, no valid parents — is a failed length-1 node (penalized, correctly); the **`ScoringJudge` unsourced residual** fires only on these, one truth call each, *reference-grounded on the retrieved corpus* `[T3]` (genuinely irreducible open-world checking). *Weighting removed for now* — every claim counts equally; vital-weighting from completeness is a possible future refinement, noted not built. A Wilson 95% CI over (successful, total) bounds the score at small counts, and the **axiom-to-derived ratio is reported** as a diagnostic so evidential breadth is visible (ten conclusions on one axiom ≠ ten independent axioms) without distorting the number. **Two-layer build (de-risking):** *Layer 1* scores every claim as an independent axiom (`grounded ∧ source-adequate ∧ attributed`) — the robust, edge-detection-free floor; *Layer 2* additively **rescues** claims that failed Layer 1 as bare by resolving their sub-DAG (§0.3), behind a config flag and gated on measured edge-recall, so weak edge detection degrades gracefully to Layer 1 rather than breaking the dimension. Per profile: Nexa's trusted corpus makes source-adequacy ≈ 1 and the bare residual ≈ 0, so accuracy collapses to ≈ grounded-axiom rate; RavenPack keeps every term live.

## 2. completeness — MAJOR · nugget recall (generated reference, deterministic scoring)

**Design flow — the honest framing first.** Completeness is the false-negative axis — of what a good answer *should* contain, how much is present — and it is structurally the hardest dimension, because the others score text that *exists* (you can parse an answer's claims) while completeness must score an **absence**: you need a "should-contain" set, and for an open question that set is in no text to parse. So completeness's **reference is generated, not parsed — and this is unavoidable, not a shortcut.** The research-backed best approximation is **nuggeting** (Voorhees 2003 → [AutoNuggetizer](https://dl.acm.org/doi/10.1145/3726302.3730090), SIGIR 2025): decompose the ideal answer into atomic facts a good answer should contain. The defensibility does **not** come from making the reference deterministic (it can't be) — it comes from the **reference-vs-scoring split**: the nugget set is **bounded generation, then frozen, pinned, and human-validated to τ ≈ 0.87**, exactly like a rubric or a benchmark test suite (generated/authored once, then run deterministically); the **scoring against it is fixed-model NLI + code**, no judge, no AI-produced numbers. Generation builds the checklist; deterministic steps grade against it.

**Where the reference comes from — three assurance modes, generation is primary, stamped on every result.** The system supports a spectrum and records which mode produced the score:
- **`generated` (primary, open-domain default)** — for arbitrary questions, the requirement facets and their nugget units are **generated per-question** `[T3-gen via GeneratorProvider]`: top-down from the question (what a complete answer demands) *and* bottom-up from the retrieved sources (material facts present in context — this half is *extractive*, parse-based, and the strongest signal). This is the honest open-domain reality: both tiers are generated, validated at τ, error-bar reported. Weakest guarantee, widest coverage.
- **`archetype` (recommended middle)** — the requirement *skeleton* is instantiated from a small, fixed, domain-independent set of ~8–12 **question-shape archetypes** (factual-lookup, comparison, causal-explanation, recommendation, enumeration, procedure, definition, …), each with a generic requirement pattern (a *comparison* must cover both sides, the stated criteria, a verdict). The shapes are human-fixed and finite even when topics aren't, so the model *instantiates a fixed structure* rather than inventing facets — bounded generation against a scaffold.
- **`templated` (strongest, closed-domain)** — for a known, recurring question-type, a human writes a short per-type checklist in `config/requirement_templates.yaml` (a five-line list of vital facets, reused across all questions of that type — *not* a per-question dataset). Here coverage is a real guarantee: if "risks" is vital, no answer omitting risk can score full completeness. This is an *upgrade path* for high-stakes types, not a prerequisite.

The three degrade gracefully: `templated` where you've invested, `archetype` for everything else, `generated` as the floor. **The assurance mode is stamped on the DimensionResult** so a reader knows whether the score rests on a human scaffold or a generated one.

**The two-tier structure (applies within whichever mode).** [HD-Eval](https://arxiv.org/pdf/2606.08625) (ACL 2024), [Qworld](https://www.alphaxiv.org/overview/2603.23522) (2026, a tree of binary criteria, every leaf unambiguous), and [question-specific rubrics beat generic](https://dl.acm.org/doi/10.1145/3702652.3744220) (2025) all support hierarchy: **Tier 1** = requirement facets (fixed in `templated`, archetype-instantiated in `archetype`, generated in `generated`), each flagged `vital`; **Tier 2** = atomic units beneath each. Every drafted unit passes the **deterministic admissibility gate** before freezing: **atomic** (one predicate / 5W1H slot, `T1Tools` parse — [Warrant Gap](https://arxiv.org/pdf/2606.24627)) `[T1]`; **self-contained** (no unresolved mention after coreferee — [ACV](https://www.mdpi.com/2227-7390/14/10/1769)) `[T1]`; **entailment-decidable** (double-NLI agreement, context-only vs context+corpus; disagreements → residual) `[T2]` — kept at one-proposition granularity, since [atomic NLI lags sentence-level](https://www.arxiv.org/pdf/2601.06528). Near-duplicates merge by `EmbeddingProvider` cosine (`≥ dedupe_tau`).

**Scoring — fully deterministic.** **Assignment** is one binary per unit: `GroundingProvider.entails(answer, unit) == E`, partial = unsupported (strict) — [ARGUE's](https://arxiv.org/abs/2501.14342) binary structure, crediting paraphrase. Code computes **strict vital recall** = `|vital supported| / |vital|` ([TREC 2025 RAG](https://arxiv.org/pdf/2603.09891)), plus `two_level_scoring.py`: **requirement coverage** = `|reqs with ≥1 supported unit| / |reqs|` (a whole missing facet is sharp signal a flat recall dilutes) and **weighted recall** = `Σ recall(r)·w(r) / Σ w(r)`, `w = 2` for vital. **Wilson CI**; **abstains below `min_n`** vital units. The generator is held to **τ ≈ 0.87** human agreement, and a periodic **human recall sample** backstops the unknown-unknown (a vital fact no pipeline surfaced) — its miss-rate is *reported as completeness's honest error bar*, not hidden. This is the one dimension where an irreducible generative step sits on the reference path; the design's answer is not to pretend otherwise but to freeze + validate + report.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| Tier-1 requirements | mode-dependent: oracle (`templated`) · T3-gen from fixed archetypes (`archetype`) · T3-gen (`generated`, **primary/open-domain**) | `requirement_templates.yaml` / `question_archetypes.yaml` / GeneratorProvider | question → vital-flagged facets; **assurance mode stamped on result** |
| Tier-2 units | T3-gen — reference build (bounded, pinned, frozen, τ-validated) | GeneratorProvider | top-down (question) + bottom-up (extractive from sources) |
| admissibility gate | T1 (atomic = 1 slot; self-contained = coref-clean) · T2 (decidable = double-NLI) — **no judge** except rare residual | T1Tools · coreferee · GroundingProvider | atomic ∧ self-contained ∧ decidable → freeze |
| dedupe | T2 — support | EmbeddingProvider | drop if `cos ≥ dedupe_tau` |
| assign (score) | T2 — primary scorer, **deterministic** | GroundingProvider | supported ⟺ `entails(answer, unit) = E` |

**Confirm:** default reference mode (`generated`/`archetype`/`templated`) + which question-types get upgraded; the archetype set; strict vs weighted; `min_n`; `dedupe_tau`; τ-validation + human-recall-sample cadence.

## 3. relevance — MAJOR · direct core + scaffolded support-tree

**Two layers, de-risked like accuracy.** Relevance has a **robust core** and a **scaffolded extension**, and only the core is load-bearing today. *Core (Layer 1, defensible now):* the **per-claim direct on-topic + on-ask check** — a fixed NLI + lexical flag ([DIVER-QA](https://arxiv.org/abs/2511.07659), matches GPT-4o 89.9%, no judge). This is the built path and the score rests on it. *Extension (Layer 2, scaffolded behind a flag):* the **support-tree + orphan-resolution** below, which *rescues* indirectly-relevant claims (a true premise connected through the answer's reasoning to an on-topic conclusion). Its edge detection is the same soft-underbelly as the claim graph (§0.3) — not yet research-strong enough to gate the score — so it is built as an **additive layer, off by default, gated on measured edge-recall**: when it underperforms, relevance degrades gracefully to the direct core rather than mis-scoring. The tree design is specified in full so it's ready to enable once edge-recall clears the bar; today it informs diagnostics, not the number.

**Design flow — the model (Layer 2, scaffolded).** A per-claim on-topic filter alone is blunt: it flags a true *premise* ("GDP down 3%, tied to pollution") as off-topic when checked in isolation, even though it supports the on-topic conclusion. So the extension evaluates relevance as a **support tree over the whole answer** — the argument-mining construction ([LLM-based argument mining](https://arxiv.org/html/2605.13793), 2026, builds directed premise→conclusion graphs; [ConvoSumm](https://arxiv.org/pdf/2106.00829)'s four steps = *extract units → classify edges → detect major claim → build graph*, exactly this pipeline):

1. **Anchors — the load-bearing seed** `[T2/T1 + code]`. The directly-relevant claims (the ones that address the question head-on) are the roots. Seed them with the **DIVER-QA on-ask check** (below), then **confirm/expand by graph centrality** — a claim many others support is central even if its own question-match was borderline ([argument-mining survey](https://arxiv.org/html/2506.16383v3), centrality for relevance/major-claim detection). Anchor recall is load-bearing (a missed anchor orphans its whole subtree), so the anchor set is **high-recall and conformal-bounded** (reuse §5 machinery, `α` tuned for recall) — "we miss a true anchor" becomes a *bounded probability*, not an unknown.
2. **Edges — the *shared* claim graph, read for reachability (not a second graph).** Relevance does **not** build its own edges — it reads the **support edges of the one `ClaimGraph`** (§0.3), the same edges accuracy reads for derivation. Those edges are developed once there (marker-propose `[T1]` → topical-narrow → `GroundingProvider.entails(A,B) ≥ tau` confirm `[T2]`, the *argumentative relation classification* task whose operational signal is entailment — [Topic-Guided KG](https://www.researchgate.net/publication/357856711), [AM survey](https://arxiv.org/html/2506.16383v3): sufficiency "operationalised with textual entailment"). Relevance's only *additional* seed is the anchor set (question-facing roots); accuracy seeds the same graph with axioms (truth-facing roots). One graph, two root sets, two projections — an orphan here and a bare claim there are the same unconnected node against a different root set (§0.3).
3. **Tree growth — iterative reachability** `[code]`. From the anchors, cycle through remaining claims attaching any with a confirmed support-path to something already in the tree; repeat to a fixpoint (handles premise→premise→conclusion *chains*). Bound the depth (`max_hops`, default 2–3) and **decay weight with depth**, so a long weak chain can't launder an orphan into relevance. Depth from anchor = the **relevance grade** (direct = 0, premise = 1, distant = 2+).
4. **Orphan resolution — the veracity layer** `[T2 + code]`. Claims with no path to any anchor are **not** simply "off-topic" — the orphan bucket holds three different things, separated by reusing existing checks: **(a) off-topic** — fails the on-topic test against the question → the true false positive; **(b) stranded / veracity-bearing** — on-topic *and* `GroundingProvider.entails` finds it **supports or *contradicts* an anchor** even though the answer drew no edge (the highest-value catch: a true, on-topic fact the answer stranded that *undercuts* its own conclusion — e.g. "primary plant sits in a flood zone" under "attractive acquisition"); **(c) independent background** — on-topic, no entailment relation to any anchor → relevant context, kept. The veracity test is directional NLI run *orphan→anchors* for the edges the answer **failed to draw** ([ReasoningFlow](https://arxiv.org/pdf/2606.05402), 2026, formalizes implicit infer/support edges). Routing: (a) penalizes relevance; (b) is **kept as relevant and routed** to logical_consistency ("conclusion inconsistent with a stated fact") and completeness ("material fact not integrated") — relevance does not itself score it down; (c) is credited as relevant.

**The relevance/soundness split (critical).** The tree confirms an edge *exists* (A entails B). Whether a *stated* inference is **valid** ("GDP down → therefore bad air", a non-sequitur the answer asserts) is **not relevance's job** — relevance maps structure; `logical_consistency` judges edge soundness ([ReasoningFlow](https://arxiv.org/pdf/2606.05402) separates *infer-present* from *infer-valid*). This stops relevance from adjudicating good-vs-bad reasoning.

**Design flow — the on-ask primitive (used to seed anchors) and scoring.** The direct on-ask check is a **fixed NLI + lexical flag, not a judge**: [DIVER-QA](https://arxiv.org/abs/2511.07659) (2025) shows NLI + a lexical-match flag **matches GPT-4o (89.9%) on long-form QA**, defensible because QA↔NLI conversion is a decades-old standard ([survey](https://arxiv.org/pdf/2402.03686)) and NLI is near-solved (~90% human agreement, [Beyond Questions](https://arxiv.org/pdf/2605.26937)), while a relevance *judge* is a known bias surface ([too generous without a reference](https://arxiv.org/html/2607.12885)). Concretely: `T1Tools` templates the ask into a hypothesis `[T1]`, `GroundingProvider.entails(claim, ask)` scores it `[T2]`, lexical overlap gives the flag `[T1]`, `on_ask = nli_E ∨ lexical`. **Methods A/B** still provide the *answer-level* signal — Method A (diagnostic): reverse-questions + Titan cosine `AR = (1/N) Σ cos(E_q, E_gi)`; Method B (default gate): `RelevanceProvider.score` thresholded in code. **Abstention** per [Knowing When You Don't Know](https://aclanthology.org/2024.emnlp-main.1268/): a proper decline to an unanswerable question → `abstain_relevant → 1.0`. **Score** = `relevance_capped_mean` over the tree: `abstain_relevant → 1.0`; else `mean` of per-claim relevance where in-tree claims score by depth-decayed grade, independent-background counts relevant, and only off-topic orphans score low — with the **off-ask cap** if the answer-level ask is unmet.

| edges | T1 marker prior + T2 confirm — primary | T1Tools (`because`…) + GroundingProvider | `A→B ⟺ entails(A,B) ≥ tau` (marker = candidate only) |

## 4. task_success — MAJOR · verifier-routed — `Σ achieved·w / Σ w`

**Design flow.** task_success asks whether the user's **objective** would actually be achieved — fit to *goal*, not question ("fix this code" answered with a correct explanation is accurate, relevant, and a task failure) — and its design correction is that this is **not irreducibly T3**: the agent-eval literature's standard is a **deterministic oracle with the judge as fallback**. Goal achievement is "typically verified by a deterministic oracle — database state, file-system state, or test-case execution" ([Hitchhiker's Guide to Agentic AI](https://arxiv.org/pdf/2606.24937), 2026); [SafeAgentBench](https://arxiv.org/pdf/2412.13178) (2024) pairs an **execution evaluator** (goal-condition state check after running the plan) with a **semantic evaluator** only where state can't capture the outcome; τ-bench-style systems use **hash-based terminal-state matching** ([Unified Framework](https://arxiv.org/pdf/2605.27898), 2026); success validation "is often rule-based" ([Generalizability survey](https://arxiv.org/pdf/2509.16330), 2025); and multi-step tasks are scored by **subgoal decomposition and summation**, SWE-bench-style ([KDD 2025 tutorial](https://sap-samples.github.io/llm-agents-eval-tutorial/2025_KDD_Evaluation_and_Benchmarking_of_LLM_Agents.pdf)). The flow: `GeneratorProvider` **infers the objective** `[T3-gen]` (intent, not literal words — "why is this slow?" implies *and how to fix it*); the question is **classified by keyword match against `config/task_templates.yaml`** `[oracle]`, which returns **verifier-tagged outcomes with weights** — the templates are human-authored and pinned, because per **Konstantinou et al. (ICST 2025)** LLM-written assertions encode the *current, possibly buggy* behaviour rather than the intended one, so outcome checks are human-validated, never agent-authored; the generator **instantiates the outcomes** for this instance `[T3-gen]`; and the **`VerifierRouter`** dispatches each outcome to its tagged verifier: *artifact-presence* → `re` pattern present `[T1]`; *executable* → currently a heuristic (code signals ∧ run-claim present) behind the config-gated `SandboxProvider` interface — **real execution when a sandbox is wired**, the single biggest determinism win still open; *state* → `expected == answer ∨ expected ∈ answer` string/hash match `[T1]`; *constraint* → includes ∧ ¬excludes ∧ word-count bounds `[T1]`; *coverage* → `GroundingProvider.entails(answer, requirement) == E` `[T2]`, reusing completeness machinery; *grounded/responsive* → reuse §1/§3 atoms; *adequacy* → the **only judge call in the dimension** ("addresses the *root* cause", "at the *right* level"). Code computes `task_success = Σ achieved·w / Σ w` (`task_success_weighted`), with a well-scoped impossible task ("can't be done because X") scoring **1.0**, parallel to relevance's abstention. For code/SQL/numeric/structured tasks the dimension is effectively `[T1]` once the sandbox exists; certification runs use pinned templates/outcome sets (the auditable path), live decomposition on novel questions is discovery and honestly more T3.

| classify + template | oracle — primary (human-authored) | `task_templates.yaml` | keyword match → tagged outcomes + weights |
| decompose outcomes | T3-gen — reference build (pinned for certification) | GeneratorProvider | instantiate template |

| route: coverage / imports | T2 — primary for these outcome types | GroundingProvider · §1/§3 | `entails = E`; reuse atoms |

## Category notes

Build §0.2 first (three dimensions consume it), then §2's units (supplying §1's weights). Responsiveness computed once (§3), imported by §1, ignored by §4. All four **MAJOR**; the only gate touching the category is fabricated-citation (Evidence build).

**Honest T3 surface after the judge-minimizing reform.** *Removed to fixed:* on-ask (NLI+lexical, DIVER-QA); admissibility atomic (typed structural) + self-contained (coref-clean); **claim decomposition** (deterministic ClausIE/PredPatt parsing — the surface-realizer is a pinned, *droppable* `[T2]` step, not open generation); **relevance** end-to-end (anchor-and-tree + orphan resolution are entailment + code, no judge). *Irreducible, score-affecting `ScoringJudge` booleans* (each reference-grounded, conformal-wrappable, none on the gate path): accuracy's **unsourced residual** (open-world fact-checking), task_success **adequacy**, relevance **abstention**, the rare **decidability/disinterest residuals**, and **abstractive-implied claims** (flagged, not silent). *Bounded generation* (`[T3-gen]`, pinned + stability-measured + τ-validated): Tier-2 unit drafting, objective/outcome decomposition, reverse-questions, the optional claim realizer. The research does **not** support claiming zero judges — forcing a "deterministic" label on open-world fact-checking or qualitative adequacy is the move [Rethinking Atomic Decomposition](https://arxiv.org/pdf/2603.28005) (2026) warns against — but it does drive the judge off the scoring path almost entirely, which the **ExplanationJudge** completes: the user-facing summary is the judge's *primary* job and it touches no number. The **ReplayVerifier proves the rest**: every score recomputes from logged atoms with no model call.

## Human assurance — where a person adds the most, and how

The system is designed so humans **certify the references and calibrate the thresholds**, not label every answer — their effort concentrates where a machine genuinely can't self-validate, and each task below is bounded and periodic, not per-run.

1. **Own the oracles.** The `requirement_templates.yaml` (completeness Tier-1), `task_templates.yaml` (task_success), and the reliability/COI lists (Evidence) are structural oracles — the coverage guarantee rests on them. A domain expert should author and periodically review these; this is the single highest-leverage human input, because everything downstream only *populates* a human-fixed scaffold.
2. **Validate the generated references to the τ bar.** For each pinned reference set (claims, Tier-2 units, triplets, outcome sets), a human labels a **small sample** and confirms machine-vs-human agreement clears **τ ≈ 0.87** (AutoNuggetizer's bar). Falling below τ is the signal a generator drifted — this is the answerability/quality meter, and it needs periodic human sampling, not exhaustive review.
3. **Build the calibration sets.** Conformal guarantees (§5, on-ask, attribution) are only as good as the human-labeled calibration data behind them: a few hundred labeled examples per stratum, refreshed on a cadence. Humans decide the **coverage target α** (how strict) and label the calibration rows.
4. **Adjudicate the flagged residuals — not the whole run.** The `ScoringJudge` residuals (unsourced-claim truth, adequacy, stranded-contradiction orphans, abstractive-implied claims) are exactly the items a fixed method couldn't settle. Surfacing these to a human reviewer as a **short queue per run** — rather than the human re-checking everything — puts expert attention only on the genuinely hard cases, and their verdicts feed back as new calibration/eval data.
5. **Run the coverage-recall audit.** Periodically, label a set of answers with *known* defects (one per error type, including blended multi-fault cases) and measure the fraction each dimension flags — this is how the "covers all error spans" claim is *tested* rather than asserted (see the construct-validity companion). Misses reveal an uncovered seam to fix.
6. **Review the ExplanationJudge output for tone/faithfulness, never for scores.** Since the summary can't move a number, human review of it is about communication quality, not integrity — a lighter touch.

The throughline: humans are the **source of the fixed references and the calibration**, and the **adjudicators of the small irreducible-residual queue** — high-leverage, bounded, periodic — while the machine does the exhaustive, reproducible scoring in between.
