# Evidence & Truthfulness — build spec (v2, implementation-synced)

Four dimensions — **groundedness, hallucination, source_quality, source_attribution** — plus the **conformal factuality** layer (§5) and the import contracts accuracy consumes (§6). Same format as `response-quality-design.md` v8: each section opens with a **design flow** paragraph (the pipeline in order, with research reasoning and exact computations in the narrative), then a compact role-annotated table. Rule throughout: **AI extracts and judges yes/no; code computes every number.**

**Why the `[T2]` NLI backbone is defensible:** this category runs almost entirely on fixed natural-language inference, which is near-solved — MNLI-class models sit at ~90% human agreement, "consistent with ceiling performance on SNLI" ([Beyond Questions](https://arxiv.org/pdf/2605.26937), 2026) — and for grounding/attribution specifically, [RefChecker](https://aclanthology.org/2024.emnlp-main.395.pdf) established fixed triplet-level checking as the gold standard, beating coarser judgment by 4–9 points. A fixed verifier is *preferable* to a generative judge here, not just cheaper: judges run [too generous without a reference](https://arxiv.org/html/2607.12885) (2026). **Two judge roles (§6):** a **ScoringJudge** (the lone residual score-affecting boolean — disinterest, after the deterministic COI rule) and an **ExplanationJudge** (read-only user summary, never an input to any score).

## 0.1 The provider roster — every tool in this category, defined

All model/tool access goes through the same typed interfaces as Response Quality (§0.1 there), constructed only by the `ProviderFactory` from `config.yaml`. Restated here in full so nothing in this doc is ambiguous:

| Provider | Signature | Mock implementation (offline) | Live implementation (target machine) | Used here by |
|---|---|---|---|---|
| **GroundingProvider** | `entails(premise, hypothesis) → {label ∈ {E,N,C}, raw_score}` | token-coverage + negation heuristic: `cov = overlap(hyp, prem)`; `cov ≥ contra_tau ∧ negation-mismatch → C`; `cov ≥ entail_tau → E`; else `N`; `raw = cov` | **Bedrock ApplyGuardrail** contextual-grounding (`score ≥ entail_tau → E`, else `N` — **no C label**) **or** **fairseq RoBERTa-large-MNLI** via `torch.hub` (native 3-way, `argmax{C,N,E}`, `raw = P(entail)`) — selected by `models.nli` | §1 per-chunk entailment builds the **support set `S`** (premise = each retrieved chunk); §3 corroboration + supports-check **reuse `S`** (no re-run); §4 attribution is a **set operation** `C ∩ S` (no new NLI) — **one verifier pass, reused by three dimensions** |
| **GeneratorProvider** | `generate(prompt, seed) → text` | parse/rule-based stand-ins | **Bedrock Claude** via `boto3` Converse, versioned prompts | §0 triplet decomposition **residual only** (parse-based PredPatt/OpenIE is primary, §0) `[T3-gen]` |
| **ScoringJudge** | `binary(question, context, reference?) → {verdict: bool, reason}` | seeded hash → stable bool | **Bedrock Claude** via Converse | §3 disinterest — now only the *residual* after the deterministic COI rule; single boolean, no numeric output |
| **ExplanationJudge** | `summarize(DimensionResults, AtomRecords) → text` | templated text stub | **Bedrock Claude** via Converse | end-of-run user-facing summary **only**; read-only over finished scores; no verdict field, never read by any `formula_id` |
| **EmbeddingProvider** | `embed(texts) → vectors` | 64-dim md5-hashed token counts, L2-normalized | **Bedrock Titan Text Embeddings V2** via InvokeModel | §1 similarity pre-filter |
| **ResolverProvider** | `resolve(url_or_doi) → bool` | fabricated-marker string check | `urllib` HEAD (HTTP 200–399) · DOI-registry lookup (config-gated) | §2 fabrication gate · §3 reachable |

Supporting non-model tools: **`T1Tools`** (stdlib `re` — citation-id parsing, number parsing, pattern checks), **`config/reliability_list.yaml`** (`[oracle]` — the human-maintained domain allow/deny-list for §3), **`CalibrationStore`** (`config/calibration/*.jsonl`, pinned human-labeled examples for §5), **`alce.py`** (citation precision/recall math), **`conformal.py` + `ConformalStratifier`** (split-conformal in stdlib `math`), the **formula registry** (`mean`, `unsupported_rate`, …), and stdlib-`math` statistics (Wilson CI, bands, min-n abstention). Packages actually imported: **pydantic**, **PyYAML**, stdlib (`hashlib`, `re`, `math`, `json`, `sqlite3`, `urllib`), **boto3**, optional **torch+fairseq**. **No numpy, no scipy, no ragas.**

**The organizing taxonomy** ([factuality-area synthesis](https://papers.lunadong.com/area/factuality)): the field separates **Source Faithfulness** — is the claim supported by the *provided* source — from **World Factuality** — is the claim *true*. Groundedness + attribution measure faithfulness; source_quality is the bridge to factuality (a source-faithful claim is only *true* if its source is trustworthy). That is exactly accuracy's `groundedness × source_quality × attribution`, with a name for each axis.

## 0. Build once — claim-triplets (`pipeline/triplets.py`)

**Design flow.** The category reuses the cached, decontextualized, verifiable claims from Response Quality §0.2 (built by **deterministic dependency-parse decomposition** there) and refines the *verification unit* one level further: each claim is decomposed into **claim-triplets** — `subject | predicate | object` — because [RefChecker](https://aclanthology.org/2024.emnlp-main.395.pdf) (Hu et al., EMNLP 2024) showed that **triplet-level checking outperforms sentence- and sub-sentence-level checking by 4–9 points** and is the current gold standard for fine-grained hallucination detection: "Einstein developed quantum mechanics in Berlin in 1905" becomes (Einstein, developed, quantum-mechanics), (Einstein, was-in, Berlin), (event, occurred-in, 1905), each checked separately so a partially-wrong compound claim can't pass whole. **Deterministic-first, consistent with §0.2:** triplet extraction is a subject-predicate-object structuring, which is exactly what **OpenIE / PredPatt** produce from the dependency parse already computed for the claims — so the primary path is *parse-based* `[T1]` (ClausIE/PredPatt predicate-argument tuples → triplets), with the **GeneratorProvider used only for the residual** claims the parser can't cleanly triple (nested/abstractive predicates) `[T3-gen]`. This is a slightly larger generative residual than claim decomposition (S-P-O restructuring is closer to generation than clause-splitting), but the *primary* path is deterministic and the generative part is pinned. Each triplet carries its claim id, citation, and source pointer; the reference is **pinned** (`pins.triplet_extractor_version`) with **stability = `|∩ triplet-ids| / |∪ triplet-ids|`** measured across N re-runs. RefChecker is backend-agnostic (any LLM backend), so nothing here touches Hugging Face.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| decompose claim → triplets | T1 parse-first (PredPatt/OpenIE) · T3-gen residual (nested/abstractive) — reference build, pinned, stability-measured | ClaimExtractor (parse) → GeneratorProvider (residual) | `subject | predicate | object`, provenance carried |
| stability | code | pipeline harness | `|∩ ids| / |∪ ids|` over N re-runs |

## 1. groundedness — MAJOR · source faithfulness — `|E| / |total|`

**Design flow.** Groundedness asks, per triplet, whether the retrieved context supports it — and the design computes it as a **per-chunk support pass** rather than one check against a merged context block, because that single pass yields groundedness, multi-source corroboration, *and* the raw material attribution (§4) needs, from one set of logged verdicts. The tools run in this order. First, the **`EmbeddingProvider`** (mock: 64-dim hashed token cosine; live: Bedrock Titan V2) is a **similarity pre-filter** `[T1]` that ranks retrieved chunks by cosine to the triplet and keeps the top-`groundedness_k` — this only *focuses* the verifier and is never the score, because embeddings can't see negation ("revenue rose" / "revenue did not rise" are near-identical vectors). Handing the verifier the whole corpus instead would *degrade* it — entailment models have a context-length sweet spot and long premises raise false Neutrals — so top-k focus is a correctness choice, not just a cost one. Second, the **`GroundingProvider`** (mock: token-coverage + negation heuristic; live: **fairseq RoBERTa-large-MNLI** for native 3-way, or Bedrock ApplyGuardrail for E/N) runs **once per kept chunk**, `entails(chunk, triplet) → {E, N, C}` — three-way per RefChecker's checker: **Entailment** (supported), **Neutral** (silent), **Contradiction** (opposite) — a fixed model, never a generative judge, which is what keeps the dimension `[T2]` and bit-for-bit replayable from stamped labels. This mirrors the ALCE construction, where citation support is an NLI entailment between passages and the statement ([ALCE](https://arxiv.org/pdf/2305.14627), Gao et al. 2023, ~85% human agreement on recall), and ALiiCE's move of assessing support at the level of individual dependency-parsed atomic claims ([LLM Sourcing survey](https://arxiv.org/pdf/2510.10161), 2025). Third, **code** collects the **support set** `S = {chunk : label == E}` (grouped by source document) and derives everything from it: **`groundedness = |E-labeled triplets| / |total triplets|`** (the RAGAS-faithfulness `|supported|/|total|` form) where a triplet is supported iff `S ≠ ∅`; **multi-source corroboration** = `|distinct documents in S|` (free, feeds §3); the per-claim boolean **`grounded = AND(all its triplets have S ≠ ∅)`** exported to accuracy; and each triplet's `raw_score` to the conformal layer (§5), where in [Mohri & Hashimoto's](https://proceedings.mlr.press/v235/mohri24a.html) framing correctness is an uncertainty problem over the *entailment set*. The **support set `S` is logged per triplet** (chunk-ids + labels), which is what makes both groundedness *and* attribution auditable from one artifact. Two honest bounds: the Bedrock backend **cannot emit C** (E/N only), so where the N-vs-C split matters (§2) run `models.nli: fairseq`; and groundedness is "supported by the *retrieved-and-filtered* context," so `groundedness_k` is set generously and is a stated parameter, not silently top-1. Numeric triplets are *not* trusted to NLI — they route to accuracy's `[T1]` numeric-edge exact-match, since entailment models miss magnitude ("$1.2B" vs "$1.3B"). *Scope statement (what this number is and isn't):* groundedness is **direct, per-claim source support** — the atomic check that builds the support set `S` and identifies the **axioms** for the claim graph (§RQ 0.3). It is deliberately **not** the answer's headline factuality number: a validly-*derived* claim ("margins improved," computed from grounded figures) correctly scores "not directly grounded" here, and that is a *routing signal*, not a failure — its transitive anchoring is scored by **accuracy's DAG resolution** (§RQ 1), which counts it as successful when its chain bottoms out in grounded axioms through valid steps. Reporting per-claim groundedness as if it measured "is the answer true" would penalize sound derivation; groundedness is the evidentiary floor and the axiom-builder, accuracy is the anchored-to-truth number.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| pre-filter (focus, never score) | T1 — support | EmbeddingProvider | top-`groundedness_k` chunks by cosine to triplet |
| per-chunk entailment | T2 — primary (fairseq 3-way / Bedrock E-N) | GroundingProvider | `entails(chunk, triplet) → {E,N,C}` for each kept chunk |
| support set + score | code | `mean` over set-ops | `S = {chunk: E}`; supported ⟺ `S ≠ ∅`; `groundedness = |supported|/|total|` |
| exports | code | — | per-claim `AND(supported)` → accuracy; `|distinct docs in S|` → §3 corroboration; `raw_score` → §5; `S` logged for §4 |

**Confirm:** verifier backend (fairseq if C matters); `entail_tau`; `groundedness_k`; atomic-triplet check upstream.

## 2. hallucination — MAJOR · unsupported rate + fabrication gate

**Design flow.** Hallucination is two different failures wearing one name, and the design splits them because one is semantic and one is fully deterministic. The **unsupported-claim rate** is read directly off §1's triplet verdicts — `unsupported_rate = 1 − groundedness` — but reported with the **Neutral/Contradiction split** (`neutral_rate = |N|/total`, `contradiction_rate = |C|/total`), because asserting *against* the evidence is a materially worse failure than asserting *beyond* it, and a single blended rate hides which one you have. The **fabrication gate** is the deterministic half `[T1]` and it gates the run: does the cited source *exist* — `cited id ∈ retrieved set` (set-membership) **or** `ResolverProvider.resolve(url/doi)` succeeds (mock: not a fabricated-marker string; live: `urllib` HEAD returning HTTP 200–399, or a DOI-registry lookup, config-gated). Existence is deliberately a **separate axis from support** — a citation can exist and not support (that's attribution's job, §4), or be fabricated outright — and the fabricated-reference problem is real at scale: audits found **50+ citation hallucinations across 300 ICLR 2026 submissions** ([CiteAudit](https://arxiv.org/html/2605.06635v1), 2026). Any `¬exists` forces the band to **R** through the standard gate path — a fabricated citation is an integrity failure, not a quality deduction.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| unsupported rate | code — reads §1 (no new model calls) | triplet verdicts | `1 − groundedness`; `|N|/tot` and `|C|/tot` reported separately |
| fabrication gate | T1 — primary, **gates** | set-membership + ResolverProvider | `exists = (id ∈ retrieved) ∨ resolve(url/doi)`; any `¬exists → FAIL (band R)` |

**Confirm:** DOI/URL registry in scope (config-gated); Contradiction weighting in downstream reporting.

## 3. source_quality — MAJOR · the bridge to world factuality — `mean(7 properties)`

**Design flow.** Source_quality turns "faithful to its source" into "trustworthy source," and it is **what accuracy imports as `source-adequate?`**. The design decision that keeps it deterministic and cheap: **it runs almost entirely on retrieval metadata + the §1 support set, with no live full-text extraction on the core path** — the credibility literature is explicit that trustworthiness is assessable from *domain-level and metadata* signals, not page content (NewsGuard/MBFC operate at the **domain** level; [ACM Web Science 2025](https://dl.acm.org/doi/10.1145/3717867.3717903) evaluates source credibility from the domain alone; the [credibility-signals survey](https://arxiv.org/pdf/2410.21360), 2024, and [CRED-1 multi-signal domain dataset](https://arxiv.org/pdf/2604.20856), 2026, organize signals as *domain reputation, author identifiability, recency, corroboration*). So the tools are lightweight. The **`ResolverProvider`** handles **reachable** — internal chunks pass by construction; external URLs are checked by a `urllib` **HEAD request** (existence, not a full GET/extraction) `[T1]`. Three properties read **retrieval metadata directly** (no fetch): **dated & fresh** — a date is present ∧ `date ≤ as_of_date` (the point-in-time window; a stale filing is a wrong filing in finance) `[T1]`; **authored** — an author/issuing body is present `[T1]`; and **reputable domain** — the domain string is matched against **`config/reliability_list.yaml`**, a human-maintained allow/deny oracle (deny→F, allow→T, unknown-under-allow-list→F, conservative) `[oracle]` — a domain-level check, exactly the NewsGuard/MBFC pattern. **Corroborated** reuses §1 for free: `|distinct documents in the support set S| ≥ corroboration_min` `[T1 count]` — independence by distinct provenance, computed off the already-logged support set, no new calls. **Supports the claim** is *already known* — it's `S ≠ ∅` from §1, not a re-run. **Disinterested** is handled **deterministic-first**: a `[T1]` conflict-of-interest rule fires first (domain/author against a **config COI deny-list**, plus an **affiliation-vs-claim-subject match** — a company's own release cited for a claim about that company), and only the genuinely ambiguous remainder falls to a **sampled `ScoringJudge`** boolean at `disinterest_sample_rate` (assumed True otherwise) — the category's *only* judge on the scoring path, now a residual after a deterministic filter. Code computes `source_quality = mean(property booleans)` per source; the exported boolean is **`source-adequate? = source_quality ≥ adequacy_threshold`**. **The one external dependency, stated honestly:** dated/authored read from retrieval metadata — *if* the retrieval layer didn't preserve it, those two properties need a live fetch, which is a config-gated **optional** enhancement (`source_quality.live_metadata_fetch`, default off), not the core path; and re-verifying a source *currently* says what was cited (freshness/tamper) is likewise optional. Per profile: Nexa's internal corpus satisfies the metadata properties by construction (`source_adequate_default` true); RavenPack's open web keeps every property live.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| reachable | T1 — primary (HEAD, not full extraction) | ResolverProvider (`urllib` HEAD) | internal pass; external URL resolves |
| dated / authored | T1 — primary (from retrieval metadata) | code · metadata | `date ≤ as_of`; author present (live fetch optional, off) |
| reputable domain | oracle — primary (domain-level, NewsGuard/MBFC pattern) | `reliability_list.yaml` | deny→F; allow→T; unknown→F |
| corroborated | T1 — primary (reuses §1 support set) | code | `|distinct docs in S| ≥ corroboration_min` |
| supports the claim | — (imported from §1, not re-run) | §1 support set | `S ≠ ∅` |
| disinterested | T1 primary (COI deny-list + affiliation) · T3 sampled residual | T1Tools · ScoringJudge | COI rule first; ambiguous remainder sampled |
| score / export | code | `mean` | `mean(properties)`; `adequate = score ≥ adequacy_threshold` → accuracy |

**Confirm:** reliability-list contents + mode; `adequacy_threshold`; `corroboration_min` + independence rule; COI deny-list + affiliation rule; `disinterest_sample_rate`; whether retrieval preserves date/author metadata (else `live_metadata_fetch`).

## 4. source_attribution — MAJOR · ALCE citation precision — `attributed?`

**Design flow.** Attribution asks whether each claim is credited to a source that *actually supports it* — distinct from correctness, since **an answer can be correct while its citations don't support its claims**, and a broken evidence trail is its own finding in a regulated setting. The key efficiency: attribution is **not a second NLI pass** — it's a set operation over §1's already-computed support set `S`, so the same logged verdicts serve both dimensions. The tools run in this order. First, **citation resolution** builds each claim's **cited set** `C` (which sources the author pointed at). Explicit pointers — `[1]`, `(Author Year)`, inline URLs — are parsed by **`T1Tools`** regex `[T1]`. Implicit citations — "According to the 10-K, revenue rose. Margins expanded." where the second claim inherits the source — are recovered in two steps that keep it auditable: **scope propagation** `[T1]` (a source introduced by an attribution cue — "according to X", "per the X filing", a closed patterned set — governs following claims until a paragraph break, a new source, or a topic shift via coref), which *proposes* the citation; then **confirmation against §1's support set** `[T2, already computed]` (the scoped source is only accepted as the implicit cite if it's in `S` — i.e. it actually entails the claim). Structure proposes, entailment disposes: a claim the author "drifted" onto within a scope but which the scoped source doesn't support won't be in `S`, so it isn't falsely attributed. Every citation is **tagged `explicit` or `implicit-confirmed`**, and the split is reported — implicit is high-confidence (NLI vouches) but still an inference about author intent, so it's labeled, not hidden ([CiteEval](https://arxiv.org/html/2506.01829), 2025, argues non-citable/implicit contexts must be handled *explicitly* rather than silently penalized or promoted). Second, **the set operations** give both ALCE metrics with no new model calls (`alce.py`): a claim is **attributed** iff `C ∩ S ≠ ∅` (a cited source is among those that actually support it); **citation precision** = `|attributed citations| / |citations|` (ALCE's "remove a cited doc, does entailment survive" reduces to this set test — [ALCE](https://arxiv.org/pdf/2305.14627) precision ~77% human agreement) and **citation recall** = `|claims with C ∩ S ≠ ∅| / |cited claims|`. The diagnostics fall out of the same sets: **`C \ S`** = cited-but-unsupported (mis-citation — the important regulated finding); **`S \ C`** = supported-but-uncited (the author under-cited a real source). This is the [ALiiCE](https://arxiv.org/pdf/2510.10161) per-atomic-claim citation model, aligned to our dependency-parsed claims. Three rules from the literature: **precision-favoring** — false positives (wrongly calling a claim attributed) are worse than false negatives ([Evidence-Based QA](https://arxiv.org/pdf/2402.08277), 2024); **non-source-referencing claims are N/A here** (no explicit cite, no scoped source in `S`) — attribution applies to the **axiom subset** the claim graph needs (only source-referencing claims should carry citations; §RQ 0.3): they route to accuracy's bare residual or, if they have inference parents, to the derived-claim path, asserted once, no double-count; and **precision ⊆ groundedness logically** — since `C ⊆ retrieved` and support is computed over retrieved chunks, `C ∩ S ≠ ∅ ⟹ S ≠ ∅`, so an attributed claim is necessarily grounded (a built-in consistency check). Because support-judging is hard even for strong models ([AttributionBench](https://arxiv.org/html/2605.06635v1): fine-tuned GPT-3.5 ~80% macro-F1), the verdict isn't trusted bare: each feeds the **conformal layer (§5)**, and the exported boolean is **`attributed? = (C ∩ S ≠ ∅) ∧ (confidence ≥ conformal threshold)`** — a verdict *with a calibrated guarantee attached*.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| resolve cited set `C` (explicit) | T1 — primary | T1Tools (regex) | parse `[n]`, `(Author Year)`, URLs → cited docs |
| resolve cited set `C` (implicit) | T1 scope-propose · T2 confirm (reuses §1) | T1Tools discourse-scope · §1 support set | scoped source accepted iff in `S`; tag `explicit`/`implicit-confirmed` |
| attribution + ALCE metrics | code — set ops over §1 `S` (no new NLI) | `alce.py` | attributed ⟺ `C ∩ S ≠ ∅`; precision, recall; diagnostics `C\S`, `S\C` |
| N/A handling | code — routing | — | no cite + not in any `S` → unsourced/derived path (no double-count) |
| score / export | code + §5 | `mean` + conformal | dimension = citation precision (recall + splits reported); `attributed? = (C∩S≠∅) ∧ conformal-confident` → accuracy |

**Confirm:** implicit-citation scope rules + whether `implicit-confirmed` counts fully or as a reported tier; precision threshold; conformal α (§5); explicit/implicit split reporting.

## 5. Conformal factuality — the statistical guarantee (`scoring/conformal.py`)

**Design flow.** The NLI verdicts in §1/§4 are strong but imperfect (~80% F1 on attribution), and a certification harness cannot rest on "the classifier is usually right." **Conformal factuality** ([Mohri & Hashimoto, ICML 2024](https://proceedings.mlr.press/v235/mohri24a.html)) converts the verifier's confidences into a **distribution-free, finite-sample guarantee**, works with **any black-box LM, and needs very few human-annotated samples** — exactly the Bedrock, no-model-internals setting. The implementation is split-conformal in pure `math`: the verifier's `raw_score` per claim/triplet is the **confidence**; on a pinned, human-labeled **calibration set** (`CalibrationStore`, `config/calibration/*.jsonl`, each row `{claim, context, label, stratum}`), nonconformity is computed over the *factual* examples as `νᵢ = 1 − confidenceᵢ`; the threshold index is `k = ⌈(1−α)(n+1)⌉` (clamped to n), `τ̂` = the k-th smallest ν, and the retention rule is **`confidence ≥ 1 − τ̂`**. The guarantee that results is
```
1 − α  ≤  P(retained claim is factual)  ≤  1 − α + 1/(n+1)
```
(the finite-sample coverage bound of split conformal; [Angelopoulos & Bates 2023](https://arxiv.org/abs/2107.07511); Vovk et al. 2005; Lei et al. 2018). Reading it: `α` is *your chosen error budget*; the **left side is the floor** — retained claims are factual at least `1−α` of the time, whatever the score distribution looks like; the **right side is the ceiling** — overshoot is at most `1/(n+1)`, the slack from picking a quantile among finitely many calibration points. Worked numbers at α = 0.05: n = 100 → band **[95.0%, 95.99%]**; n = 1000 → **[95.0%, 95.1%]**; the floor arrives immediately even at small n (hence "very few samples") and more data only tightens the band — letting the harness state, defensibly: *"of the claims retained as source-supported, at least 95% are genuinely supported, calibrated on n human-verified examples."* Sub-claim-level use is validated across domains ([Conformal-RAG](https://arxiv.org/pdf/2603.16817), 2025; TRAQ 2023; Conflare 2024). **The caveat is that the guarantee is *marginal*** — it holds on average, not automatically within every subgroup (97% on easy claims and 92% on hard ones still averages 95%); per [Adaptive Conformal Prediction](https://arxiv.org/html/2604.13991v1) (2026) a global threshold over-covers hard strata and under-covers easy ones, so when a regulator needs uniform coverage the **`ConformalStratifier`** calibrates per stratum (question-type / source-type, config `per_stratum`). Everything here is deterministic given the calibration set + α: the threshold, retention, and band `[1−α, min(1, 1−α + 1/(n+1))]` are stamped on the DimensionResult, and the layer **abstains below `min_calibration_n`**.

| Step | Tier | Provider/tool | Computation |
|---|---|---|---|
| confidence | T2 — input (from §1/§4 raw_scores) | GroundingProvider | per calibration example + per live claim |
| calibrate | code — primary (pure `math`) | `conformal.py` + CalibrationStore | `νᵢ = 1−confᵢ`; `k = ⌈(1−α)(n+1)⌉`; `τ̂` = k-th smallest; threshold `= 1−τ̂` |
| retain + guarantee | code | — | retain ⟺ `conf ≥ threshold`; band `[1−α, 1−α+1/(n+1)]` stamped; abstain if `n < min_calibration_n` |
| per-stratum | code | `ConformalStratifier` | same, grouped by config strata (marginal→conditional coverage) |

**Confirm:** `α`; calibration-set size + refresh cadence; `per_stratum` keys.

## 6. Contracts — what accuracy imports (no stubs remain)

- `GroundingProvider.entails(premise, hypothesis) → {label, raw_score}` — **one verifier pass, reused three ways**: §1 runs it per retrieved chunk to build the **support set `S`**; §3 reads `S` for corroboration + supports; §4 is the set operation `C ∩ S`, no new NLI. Backend by `models.nli`; Bedrock = E/N only, fairseq = full 3-way.
- `SourceQualityProvider.adequate(source, claim) → bool` — §3's `mean(properties) ≥ adequacy_threshold`, on metadata + `S`; `source_adequate_default: true` for the Nexa profile.
- `AttributionProvider.attributed(claim, cited_chunk) → {bool, confidence}` — §4's `C ∩ S ≠ ∅` ∧ §5's conformal retention.
- All emit AtomRecords; every score above replays from `atom_ids + formula_id` via the ReplayVerifier with no model call — **and because §3/§4 reuse §1's logged support set, they replay as pure set operations.**
- **Judge quarantine (shared with Response Quality §0.5):** the **ScoringJudge** here is a single boolean, only for the disinterest *residual*, reference-groundable; the **ExplanationJudge** writes the user-facing summary *after* scoring, read-only, and is never an input to any `formula_id` — "explain, never override" is structural.

**Development summary** — where each tier does work:

| Dimension | formula_id | T1 | T2 (fixed NLI/grounding) | T3 (residual only) |
|---|---|---|---|---|
| groundedness | `mean` | pre-filter; support-set ops | per-chunk 3-way entailment — primary (builds `S`) | gen: triplets (pinned) |
| hallucination | `unsupported_rate` | fabrication existence — primary, **gates** | reads §1 verdicts | — |
| source_quality | `mean` | metadata + COI + corroboration (reuses `S`) — primary · oracle list | supports = `S≠∅` (imported) | ScoringJudge: disinterest *residual* only |
| source_attribution | `mean` (precision) | citation parse; `C ∩ S` set ops; diagnostics | implicit-cite confirm (reuses `S`) | — |
| conformal (§5) | — | calibration + retention (pure math) | confidences in | — |

The category's single gate (fabrication) is pure `[T1]`; the **only** score-affecting judge is the disinterest residual (a single conformal-wrappable boolean, off the gate path); the `[T3-gen]` reference builder is pinned triplet extraction alone. The architecture's efficiency and auditability come from the same fact: **one per-chunk entailment pass produces the support set `S`, and groundedness, corroboration, source-support, and attribution are all set operations over `S`** — every number is a formula over stamped labels, replayable with no model call, with §5 adding the calibrated guarantee on the hardest verdicts and the ExplanationJudge carrying the user summary without touching any score.
